> 测试日期：2026-05-25 | W2 Day 4
> 模型：DS V4-Flash / DS V4-Pro / Qwen Plus (DashScope)
> 方法：两轮共 10 条系统化 prompt，覆盖翻译、推理、代码、指令遵循、中文创作 5 个维度

## 重要发现：deepseek-chat 已经是 V4

2026.04.24 DeepSeek 发布 V4 后，`deepseek-chat` 和 `deepseek-reasoner` 在过渡期内自动映射到 V4-Flash。**你调的是 V4，不是 V3。** 过渡期至 2026.07.24，届时旧名失效。

## 行为差异深入

### 1. 中文母语度

```
Qwen    ██████████  母语级 —— "所以啊"、"刚洗完脸"、"天光慢慢软下来"
V4-Pro  ████████    高级非母语 —— 偶有佳句但不稳定，翻译会退步
V4-Flash ██████     够用但生硬 —— "太炸了"暴露非母语本质
```

Qwen 的中文是母语级语感，DS 的中文是"学得很好但偶尔露馅"。这个差距 V4-Pro 缩小了但没追平。

### 2. 输出哲学

| | DS Flash | DS V4-Pro | Qwen |
|------|---------|-----------|------|
| 风格 | 问多少答多少 | 多给一点 | 知无不言 |
| 推理风格 | 清单式 | 清单式 | 学术论文式 |
| 翻译风格 | 忠实原文 | 忠实原文 | 多版本 + 术语对照 |

### 3. V4-Pro 的尴尬定位

在翻译场景上 Pro 不仅没进步还退步了（"backup nodes" vs Flash 的 "standby nodes"），但耗时和 Token 却是 Flash 的 3-5 倍。Pro 唯一展现优势的是中文创作，但也没超过 Qwen。

### 4. 速度异常

Qwen 速度波动极大：口语翻译 1.39s 极快，Day 4 数学题曾到 42s。初步判断是服务端排队问题，非模型本身速度。用正确的模型名（`qwen-plus`）后波动减小。

## 选型建议

| 场景 | 首选 | 原因 |
|------|------|------|
| 中文对话/客服 | **Qwen** | 母语级中文，DS 追不上 |
| 中文内容创作 | **Qwen** / V4-Pro | 差距不大，Pro 偶尔出彩 |
| 技术翻译（中→英） | **Qwen** | 术语最精准 |
| 逻辑推理 | **DS Flash** | 简洁高效，Qwen 容易过度推理 |
| 数学/计算 | **DS Flash** | 又快又省，正确率相同 |
| 代码生成 | 任一 | 表现接近 |
| 成本敏感 | **DS Flash** | Token 省 70%，延迟低 85% |
| 深度分析/报告 | **Qwen** | 多版本、术语解释自带附加值 |

## 核心结论

> 1. **正确率相同不代表等价。** Qwen 比 DS Flash 多消耗 3-6 倍资源实现同样正确的结果。
> 2. **中文本土化是千问的护城河。** 即使 V4-Pro 也追不上 Qwen 的母语级语感。
> 3. **贵的模型不一定更好。** V4-Pro 在翻译上反而退步。选模型要看具体任务，不是看价格。
> 4. **模型名会骗人。** deepseek-chat 背后已经是 V4，定期看 Changelog 才知道自己在调什么。
